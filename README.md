# gyres-experiment-template

A template repository for **personal ocean-gyres experiment ledgers**.

**ocean-gyres** is a differentiable multi-layer shallow-water ocean model in
JAX ([IGE-OPERA/ocean-gyres](https://github.com/IGE-OPERA/ocean-gyres)). This
template gives every user/clone of that model a ready-made **experiment
ledger**: a git repository that records *what was run, where, how, and what
came of it* — never the model code, and never the output data.

Use **"Use this template"** on GitHub (or `gh repo create <name> --template
IGE-OPERA/gyres-experiment-template`) to instantiate your own ledger.

## The reproducibility chain

Every experiment directory in `runs/` must keep this chain unbroken:

```
run.yaml (intent) → config.yaml (resolved) → run_manifest.json (provenance)
                                                ↕
                                     gyres.commit resolves to a commit on
                                     the protected main of IGE-OPERA/ocean-gyres
```

- `run.yaml` — authored by you: which preset, what overrides, which machine
- `config.yaml` — generated by `bin/run-experiment init`: the fully resolved
  experiment (grid, physics, run, io)
- `run_manifest.json` — written by `gyres run`: exact code commit, config
  sha256, dataset checksums, python/jax versions, machine, final
  `state_digest`

If an experiment cannot be reproduced from what is committed, the system has
failed.

## Quick start

```bash
# 0. Prerequisites: an ocean-gyres checkout (default: sibling directory
#    ../ocean-gyres; override with $GYRES_DIR or machines/*.yaml gyres_dir)

# 1. Describe this machine (once)
bin/detect-machine --write
$EDITOR machines/<hostname>.yaml

# 2. Declare an experiment
mkdir -p runs/macbook_2026-10-15_hh00-smoke
cat > runs/macbook_2026-10-15_hh00-smoke/run.yaml <<'EOF'
preset: hh00
machine: <hostname>
resolution: 4
overrides:
  n_steps: 100
status: planned
EOF

# 3. Init (writes config.yaml + run.sh into the run directory)
bin/run-experiment init runs/macbook_2026-10-15_hh00-smoke

# 4. Run (direct, sbatch, or oarsub depending on the machine config)
bin/run-experiment run runs/macbook_2026-10-15_hh00-smoke

# 5. Reproduce later — from the committed provenance
bin/run-experiment reproduce runs/macbook_2026-10-15_hh00-smoke
```

`status` in `run.yaml` follows the lifecycle:
`planned | submitted | running | completed | failed`.

## How to read an experiment

| File | What it tells you |
|------|-------------------|
| `run.yaml` | Intent: preset, overrides, machine, status |
| `config.yaml` | Fully resolved configuration (generated by init) |
| `run_manifest.json` | Exact software environment + results (written by `gyres run`): code commit, config hash, dataset sha256, env, `state_digest` |

Reproduce any experiment with `bin/run-experiment reproduce <run-dir>` —
this verifies the manifest, the recorded ocean-gyres commit, and re-runs.

## Layout

- **`runs/`** — one self-contained directory per experiment
  (`<nickname>_<YYYY-MM-DD>_<description>`) with declaration, resolved
  config, provenance, and per-run analysis scripts
- **`reports/`** — dated, shareable series reports (`series.yaml` + Markdown
  + companion image folders)
- **`machines/`** — machine configurations (scheduler, paths, devices)
- **`bin/`** — `run-experiment`, `detect-machine` helpers
- **`analysis/`** — reusable diagnostics and cross-experiment intercomparisons

Conventions for agents and humans: [`AGENTS.md`](AGENTS.md).

## Prerequisites

- An ocean-gyres checkout with `uv sync` done (default sibling `../ocean-gyres`)
- `python3` with `pyyaml` available for the bin helpers (the checkout's
  `.venv` is used automatically when present)
