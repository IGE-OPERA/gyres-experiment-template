# AGENTS.md

This document explains the purpose, philosophy, boundaries, and working
conventions of this ledger for AI coding agents.

## 1. Purpose

This repository is a **personal experiment ledger** for ocean simulations run
with [ocean-gyres](https://github.com/IGE-OPERA/ocean-gyres).

It records **what was run, where, how, and what came of it** — not the model
code, and not the output data.

**Reproducibility is the core guiding principle.** Every experiment must be
reconstructable from its provenance records. The full chain
`run.yaml → config.yaml → run_manifest.json` must be complete and unbroken
for every experiment. If an experiment cannot be reproduced from what is
committed, the system has failed.

Goals, in priority order:

1. **Reproducibility** — every completed experiment has a `run_manifest.json`
   with enough information to reconstruct the exact run (code commit, config
   hash, dataset checksums, environment, final state digest)
2. **Cross-machine synchronisation** — design experiments locally, push,
   pull on a remote HPC machine, run, push back the provenance records
3. **Auditability** — see at a glance what experiments exist, their status,
   and which machine they ran on

## 2. Philosophy

**Reproducibility chain.** The following chain must be unbroken for every
experiment:

```
run.yaml (intent) → config.yaml (resolved) → run_manifest.json (provenance)
                                                    ↕
                                gyres.commit resolves to a commit on the
                                protected main of IGE-OPERA/ocean-gyres
```

- `run_manifest.json` is the permanent provenance record — never delete or
  modify it (the `result` / `execution` sections written by `gyres run` at
  completion are the only in-place updates, and they are written by the tool,
  not by hand).
- `gyres.commit` in the manifest must be a real commit of
  `IGE-OPERA/ocean-gyres` (verify with `gyres reproduce` or
  `git merge-base --is-ancestor <sha> origin/main` in the checkout). If it
  is `null`, the chain is broken.
- `series.yaml.gyres_commit` in `reports/` must match the manifests of all
  experiments in the series.
- Never commit an experiment directory that is missing `config.yaml` or
  `run_manifest.json` after the experiment has been run.

**Reproducibility verification checklist.** Before considering an experiment
complete, verify:

- [ ] `config.yaml` matches `run.yaml` + overrides
- [ ] `run_manifest.json` exists and its `config.hash` matches `config.yaml`
      (`gyres reproduce` verifies this)
- [ ] `gyres.commit` is non-null and reachable on `origin/main` of ocean-gyres
- [ ] After the run: `result.state_digest` + `execution.hostname/date` present
- [ ] `series.yaml.gyres_commit` (if in a series) matches the manifest

**Experiments as data, not code.** This repo contains declarative specs
(`run.yaml`) and generated records (`config.yaml`, `run_manifest.json`). It
does not contain model code or simulation output.

**Git as the transport.** Synchronising between your laptop and an HPC
machine means `git pull` / `git push`. The `run.yaml` file is the portable
unit of intent — write it locally, push, pull on the remote, init-and-run.

**Separation of concerns.** Hard boundaries:

- **ocean-gyres** (model code) → lives in its own checkout (`gyres_dir`),
  never edited here
- **Output data** (NetCDF, NPZ, logs) → git-ignored; outputs land inside the
  run directory and are excluded by `.gitignore`, referenced through the
  manifest
- **Preset physics** → single source of truth is `gyres.configs.presets` in
  the ocean-gyres repo; this ledger never restates physics parameters

**Analysis is a first-class citizen.** Per-experiment analysis scripts live
alongside their experiments in `runs/<...>/`, making each run directory
self-contained. Reusable diagnostic functions live in `analysis/`.
Jupyter notebooks are committed with output cells stripped (nbstripout).

## 3. Repository Map

```
runs/                  One subdirectory per experiment — the core of this repo
  <nickname>_<YYYY-MM-DD>_<description>/
    run.yaml           Declarative intent (preset, overrides, machine, status)
    config.yaml        Resolved configuration (generated by bin/run-experiment init)
    run_manifest.json  Provenance record (written by `gyres run`; includes
                       result.state_digest + execution.hostname/date after a run)
    notes.md           Free-form human notes on setup, results, observations
    *.py / *.ipynb     Analysis scripts and notebooks (self-contained;
                       run_dir = Path(__file__).resolve().parent)
    *.png              Output images from analysis (committed — small)
    *.nc / *.npz       Model output data (git-ignored — never commit)

reports/               Dated, shareable experiment-series reports
  <YYYY-MM-DD-description>/
    series.yaml        Series manifest (gyres_commit, machine, experiments)
    <YYYY-MM-DD-title>.md        Dated report
    <YYYY-MM-DD-title>/          Companion folder for images

machines/              Machine configurations (tracked here — personal repo)
  _template.yaml       Schema reference
  <machine>.yaml       Actual configs (absolute paths OK)

bin/
  run-experiment       init | run | record | reproduce
  detect-machine       Auto-detect current machine by hostname

analysis/              Reusable diagnostics + intercomparisons
```

## 4. Boundaries

### What this repo IS

- A ledger of experiments: intent, configuration, provenance, human notes
- A home for analysis scripts and notebooks
- A place to track personal machine configurations
- A synchronisation layer between development and HPC machines

### What this repo is NOT

- **Not the model.** ocean-gyres source code is never edited here.
- **Not a data store.** No NetCDF, Zarr, or large binary files.
- **Not an archive.** Raw output files are not committed; `run_manifest.json`
  and `config.yaml` capture enough to locate and reproduce the output.
- **Not a fork.** Depends on the ocean-gyres checkout as a sibling
  (`gyres_dir`), never vendors its code.

## 5. Experiment Naming Convention

```
<nickname>_<YYYY-MM-DD>_<description>
```

- `<nickname>` — from `machines/<machine>.yaml` `nickname` field
- `<YYYY-MM-DD>` — date the experiment was declared
- `<description>` — short hyphen-separated description

Examples: `macbook_2026-10-15_hh00-smoke`, `jeanzay_2026-11-01_nw2-gyre`.

The nickname encodes the (intended) execution machine directly in the
directory name.

## 6. The `run.yaml` Format

```yaml
preset: hh00                  # preset from gyres.configs.presets (or 'config:')
config: ""                    # alternative: path to an existing experiment YAML
machine: <hostname>.yaml      # optional; auto-detected from hostname if omitted
resolution: 4                 # optional grid resolution override (presets only)
overrides:                    # optional Experiment-field overrides
  n_steps: 100
  dt: 600
status: planned               # planned | submitted | running | completed | failed
notes: ""                     # optional free text
```

Field rules:

- `preset` / `config` — exactly one is required; `preset` must exist in the
  gyres CLI registry (`gyres list-presets`)
- `overrides` — keys must be `Experiment` fields (`dt`, `n_steps`, `tau0`,
  `wind_profile`, `bathymetry`, `solver`, `io_format`, `io_interval_s`,
  `io_variables`, …); init validates and fails loudly on unknown keys
- `machine` — YAML filename in `machines/`; auto-detection matches
  `hostname -s` against the `hostnames` lists

**Lifecycle:**

| Status | Expected files in `runs/<name>/` |
|--------|-----------------------------------|
| `planned` | `run.yaml` only (optionally `notes.md`) |
| `submitted` | `run.yaml`, `config.yaml`, `run.sh` |
| `running` | `run.yaml`, `config.yaml`, `run.sh`, `run_manifest.json` |
| `completed` | all of the above with `result.state_digest` + `execution.*` in the manifest, `notes.md` |
| `failed` | all of the above, `notes.md` with error details |

## 7. Working Conventions

### Cross-Machine Workflow

1. **Design locally**: write `runs/<...>/run.yaml`, commit, push
2. **Execute remotely**: pull; `bin/run-experiment init` + `run`
   (machine auto-detected); update `status`; commit and push
3. **Review locally**: pull; read the manifest and `notes.md`; write analysis
   scripts in the run directory

### `bin/run-experiment` Commands

- `init <run-dir>` — reads `run.yaml`, writes `config.yaml` (with
  `io.dir: "."` so all outputs land in the run directory) and a
  scheduler-aware `run.sh` (direct / `#SBATCH` / `#OAR` headers from
  `machines/*.yaml`, `env_setup` embedded). Note: init of a bathymetry
  preset (e.g. `hh00`) fetches the bathymetry dataset and writes resolved
  masks into `config.yaml`.
- `run <run-dir>` — executes `run.sh` (directly, `sbatch`, or `oarsub -S`);
  updates `status`. The `gyres run` inside `run.sh` stamps
  `result` + `execution` into `run_manifest.json` at completion.
- `record <run-dir>` — regenerates `run_manifest.json` + `config.yaml` from
  `config.yaml` without running (used after manual config edits).
- `reproduce <run-dir>` — `gyres reproduce .` inside the run directory
  (verifies config hash + code commit; writes to
  `reproductions/<timestamp>/`).

### `bin/detect-machine`

Matches `hostname -s` against `machines/*.yaml` `hostnames` lists.
`--write` creates a starter config for the current machine; `--verbose`
prints machine file + nickname. Used by `run-experiment` when `machine` is
omitted in `run.yaml`.

### Machine Configs

Machine YAML files live in `machines/` and may contain absolute paths
(personal repo). Key fields: `nickname`, `hostnames`, `scheduler`
(`null|slurm|oar`) + partition/account/walltime/mem/gres/qos or OAR
project/resources/properties/types, `devices`, `precision` (`fp64` is the
gyres default), `gyres_dir` (ocean-gyres checkout), `gyres_python`
(explicit interpreter override), `env_setup` (embedded into every generated
`run.sh`). Full schema: `machines/_template.yaml`.

### Analysis Scripts and Notebooks

- Per-experiment scripts/notebooks go in `runs/<experiment>/` — use
  `Path(__file__).resolve().parent` as `run_dir`; locate output data via the
  manifest, never hardcoded HPC paths
- Reusable importable diagnostics go in `analysis/` (functions taking
  `xarray.Dataset`, no side effects)
- Cross-experiment intercomparisons go in `analysis/intercomparisons/`
- Notebooks committed with output cells stripped (nbstripout)

## 8. What Agents Should Do

### Create a new experiment

1. Determine the machine nickname from `machines/<machine>.yaml` (or
   `bin/detect-machine`)
2. Create `runs/<nickname>_<YYYY-MM-DD>_<description>/run.yaml` with
   `preset`, optional `machine`/`resolution`/`overrides`, `status: planned`
3. Verify the preset exists (`gyres list-presets`)
4. Optionally add `notes.md` with context
5. Do NOT run `init`/`run` — execution is the user's decision

### Record results for a completed experiment

1. Verify `config.yaml` and `run_manifest.json` exist
2. Verify the manifest has `result.state_digest` and `execution.*`
3. Update `status` in `run.yaml` to `completed` or `failed`
4. Do NOT hand-edit `config.yaml` / `run_manifest.json` — regenerate via
   `bin/run-experiment init|record` instead

### Reproduce a past experiment

1. Read `run_manifest.json` in the run directory
2. `bin/run-experiment reproduce runs/<dir>` (add `--check` by invoking
   `gyres reproduce --check` for bit-exact comparison when available)

## 9. What Agents Must NOT Do

- **Never edit the ocean-gyres checkout from this repo** — model changes
  belong to the model repo's PR flow
- **Never commit data files** — no NetCDF, Zarr, NPZ or large binaries
  (small PNG analysis images in `runs/` and `reports/` are the exception)
- **Never modify generated files by hand** — `config.yaml`,
  `run_manifest.json`, `run.sh` are tool outputs; fix `run.yaml` and re-init
- **Never delete `run_manifest.json`** — permanent provenance record
- **Never commit a completed experiment with `gyres.commit: null`** in the
  manifest — the chain is broken; re-run from a proper checkout
- **Never change `status` without user confirmation** — status reflects
  real-world state
- **Never run experiments automatically** — wait for the user to decide
  when and where to execute
- **Never hardcode machine-specific absolute paths** in `run.yaml` or
  portable analysis scripts — they belong in `machines/*.yaml`
- **Never modify a dated report after it has been shared** — write a new
  dated report instead

## 11. Experiment Series and Reports

Experiments naturally come in **series** — groups of related runs sharing a
configuration, machine, and comparison goal. A series lives in
`reports/<YYYY-MM-DD-description>/`:

```yaml
# series.yaml
name: hh00 resolution sweep
gyres_commit: 60e15287964c255d54a0290953b4179b7a0526aa   # shared ocean-gyres commit
machine: Juliens-MacBook-Pro.yaml
date: 2026-10-15
experiments:
  - macbook_2026-10-15_hh00-smoke
status: running            # planned | running | completed
description: >
  Smoke-test the ledger chain and establish a baseline HH00 spin-up.
```

Rules:

- `gyres_commit` must match the `gyres.commit` recorded in every member
  experiment's manifest (all runs of a series share one code version)
- `experiments` references existing `runs/<...>/` directories — no duplication
- Reports are dated (`<YYYY-MM-DD>-<title>.md`) with a companion image folder
  of the same name; images are **copied** (not symlinked) so the report is
  self-contained; PNGs are committed (small); reports are immutable once
  shared; no raw data in reports.
